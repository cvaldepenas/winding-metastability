## New and residual inconsistencies, severity-ranked

### BLOCKING 1 -- complete-file digest and in-file state cannot transition honestly

A2b defines the normative body as the complete file (`72-75`); the state
token is inside that file (`34`); any normative byte change voids approval
(`335-345`); HG1 is supposed to move the state (`347-355`); and the guard
uses the resulting token and requires a pointer binding the current file
digest (`guard:173-242`). The completed transition fixture demonstrates the
cycle directly.

Serving a post-state candidate does not solve it: before HG1 it lacks the
HG1 pointer and fails M5-STATE, while G1 says a gate without a same-day PASS
is not servable (`469-474`). Serving the PASSing PROPOSED digest and editing
state afterward changes the gated object. A mutable state record must be
separated from the immutable normative body, or the transition/digest
protocol must explicitly bind a post-state object without relying on a
pre-existing gate claim.

### BLOCKING 2 -- v4.1's own HG1 request names v4

The document identifies itself as v4.1 (`1`, `6`), but HG1 instructs the
lead/operator to request and ratify `v4` (`347-350`), and the final verdict
again says `v4` (`583-591`). A2 requires the exact version. The operator
cannot follow both clauses for one gate; the version must be made internally
consistent before HG1.

### MAJOR 1 -- form enforcement still accepts forms the charter says it rejects

S3/G2 promise closed A/B/C schema, link/embed/reparse rejection, governing
gate binding, neutral pointers, and state enforcement. The guard implements
a narrow byte check, filename regex, filename/digest dictionary, and state
token/pin check. The completed schema and wrong-gate-class fixtures isolate
the mismatch. A5's authenticity disclaimer is correct but does not resolve
a form-checking claim: these cases concern the form the guard says it checks.

### MAJOR 2 -- transition and dependency semantics are not represented

The registry grammar contains no action, version, scope, predecessor,
dependency set, suspension, or revocation field. Consequently M5-STATE
cannot distinguish an authenticated transition from a changed token, and
M5-DIGEST cannot implement automatic source-dependent suspension. The
REVOKED consistency fixture confirms the transition half.

### MAJOR 3 -- the point-in-time downgrade was not propagated through G2

G1 is honest about point-in-time behavior, but Gate Standard/G2 retain
"every access, mutation, commit, and export," and G4 retains an unimplemented
baseline-tree prerequisite. Those statements should either become explicit
operator run duties consistent with G1 or be backed by a supplied mechanism.

### MAJOR 4 -- quarantine and incident routing remain internally inconsistent

C2 says quarantine is procedural, while T-REGISTRY says the same content is
inaccessible. Separately, P8 bars a content-reading context from later
writing/reviewing/advising formal-framework (`171-181`), while section 9
requires interpretation incidents to be recorded in the formal-framework
cross-provider ledger (`565-569`). No clean handoff route is defined that
both preserves P8 and supplies that required record.

### MINOR 1 -- residual naming overstates the repaired R2/control versions

D1 and S2 still call R2's grammar "inert" (`198-200`, `309-310`) although R2
correctly calls it restricted/low-risk. The guard also prints
`coherence_guard v1` while the served input and charter call it v1.2. The
blob digest prevents byte ambiguity, so this is traceability/wording rather
than a separate control failure.

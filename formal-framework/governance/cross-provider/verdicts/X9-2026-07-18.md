## FATAL

### F1 — Gate records authenticate Git bytes, not the human decision

- EXACT LOCATION: HG-RECORD, lines 131-138; HG1 COUNTERSIGN, lines
  148-160; the same evidence model is reused by HG2-HG5, authorship,
  suspension, and revocation.
- ABUSE MECHANISM: The governed session writes the alleged verbatim
  operator words, commits them, then writes an alleged countersign that
  names the real prior commit. Git proves only that those strings were
  committed in that order. It does not prove the human originated either
  statement; ordinary Git author metadata is also forgeable. The v3
  history expressly acknowledges this as “double-fabrication,” so the
  residual is known rather than hypothetical. A future repository-only
  verifier cannot distinguish a real gate from an agent-fabricated chain.
- PROPOSED REPLACEMENT TEXT: “Every gate is constituted only by an
  operator-originated, independently verifiable event or cryptographic
  signature over `{gate-id, action, canonical path, exact normative-body
  digest, version, scope fields, nonce, timestamp}`. The verification key
  and event origin are pinned outside every agent-writable location. An
  agent-written quotation, transcript, summary, Git author field, commit,
  or countersign is not gate evidence. If origin verification is
  unavailable, the gate is unsatisfied.”

### F2 — “Guard wired and passing” is a forgeable and non-continuous gate

- EXACT LOCATION: HG1 lines 158-160; GUARD EXTENSION lines 226-240.
- ABUSE MECHANISM: No canonical guard path, implementation digest, test
  digest, trusted runner, required hook, candidate tree hash, or durable
  run attestation is named. The governed session can install an always-
  passing guard, run a benign version once, assert success, or modify it
  after ratification. A directory scan also cannot enforce chat, semantic
  paraphrase, or egress restrictions.
- PROPOSED REPLACEMENT TEXT: “Entry into force requires an external
  attestation naming the guard path and blob digest, test-suite digest,
  exact candidate tree hash, successful run ID from an operator-controlled
  runner, and evidence that the check is mandatory and fail-closed on
  every governed write, commit, merge, read, and export. Layer writers
  cannot modify or bypass the guard. Rules the guard cannot observe must
  have separately pinned platform enforcement or remain non-grantable.”

### F3 — Readings can legalize their own semantic overreach

- EXACT LOCATION: D1 lines 93-99; B/C lines 120-125; HG2 lines 162-165;
  guard honesty lines 237-240.
- ABUSE MECHANISM: HG2 approves dictionaries only. A reading is expressly
  unapproved; its “lawfulness” is equated with its self-authored compliance
  block, while connective ordinary language is unrestricted. The guard
  checks only form. An author can put a world, agency, causal, or purpose
  claim in purported connective prose, attach a complete but false block,
  and obtain formal guard PASS. Type C provides the same wrapper for a
  draft that functions as a reading.
- PROPOSED REPLACEMENT TEXT: “Every reading sentence must be classified as
  an exact corpus-pointer statement, approved dictionary substitution,
  paired baseline comparison, blocked-inference mention, or approved
  formal correspondence. Connective language is limited to an enumerated
  semantically inert grammar and introduces no predicate or referent. A
  compliance block is metadata, never authorization. Every reading version
  requires HG2-R approval bound to its exact payload, dictionary, charter,
  and corpus digests before any use, rendering, quotation, routing, or
  sharing. Type C may contain row proposals and review annotations only.”

### F4 — The pre-HG1 closure is self-negating

- EXACT LOCATION: Status lines 19-25 and final verdict lines 256-261.
- ABUSE MECHANISM: The proposal says it has zero authority until HG1, then
  uses that zero-authority text to declare the directory closed and
  pre-HG1 drafting a violation. The only cited external firewall expressly
  stops outside this directory. Material can therefore be developed before
  HG1, removed before the guard runs, and recreated afterward without
  violating any already-in-force rule identified by this charter.
- PROPOSED REPLACEMENT TEXT: “This proposal creates no pre-ratification
  duties. HG1 is unavailable unless an already-in-force external
  moratorium, identified by canonical path and immutable digest, and a
  fail-closed write control, identified by implementation digest, have
  governed this directory since a pinned baseline tree hash. Material
  lacking authenticated post-HG1 creation provenance is ineligible for
  admission or reuse.”

### F5 — HG2 approvals bind mutable labels rather than exact payloads

- EXACT LOCATION: D3 lines 103-104; HG-RECORD lines 131-138; HG2 lines
  162-165; reading pins lines 120-123.
- ABUSE MECHANISM: Non-HG1 gates require only object and version; the
  session later chooses the pinned commit. Appending the approval record to
  the dictionary changes the approved file. The guard does not recompute a
  dictionary normative-body digest, and readings pin only a version label.
  Vocabulary or licensed inferences can be replaced under the same label
  while retaining a facially valid record.
- PROPOSED REPLACEMENT TEXT: “Normative payloads and gate records are
  separate objects. Every gate statement itself names the exact normative-
  body digest. The guard recomputes it on every access, mutation, commit,
  and export. Every dependent reading pins the exact dictionary, charter,
  and source-corpus payload digests. Any normative byte change voids the
  approval and requires a new version and gate.”

### F6 — P3 and the authorship design permit interpretation-tainted ingress

- EXACT LOCATION: P3 lines 47-56; P6 lines 65-77; AUTHORSHIP GATE lines
  174-183.
- ABUSE MECHANISM: P3 deliberately permits an interpretation-originated
  reading-annex to be handed to a formal-framework gate after HG4. The
  authorized interpretation writer is the MATH-lane lead, who can also
  return to formal work in the same model context. Vocabulary, theorem
  selection, renamed variables, or a structural idea can then enter sealed
  mathematics without appearing as a recognizable quotation or paraphrase;
  a later certification launders it back into P1 “certified ground.” P6
  regulates artifacts, not latent session influence.
- PROPOSED REPLACEMENT TEXT: “No interpretation artifact, annex, excerpt,
  paraphrase, structural derivative, term choice, or layer-originated
  proposal may be submitted to or used to initiate a formal-framework gate;
  HG4 cannot waive this rule. Any context that accesses non-pointer
  interpretation content is permanently INTERPRETATION-TAINTED and may not
  write, review, gate, select, summarize, or advise formal-framework,
  physics, publication, or candidate-selection work. A mathematical
  refinement must be independently initiated in a fresh clean-room context
  with no layer-derived prompt.”

## MAJOR

### M1 — The containment boundary contradicts required Git and chat storage

- EXACT LOCATION: P6 lines 65-75; HG-RECORD lines 135-138.
- ABUSE MECHANISM: Committing a layer file stores its full content under
  `.git/objects`, outside `research/interpretation/`; pushing creates a
  remote copy. The allowed operator chat normally persists the source
  message in the same transcript/search systems that P6 requires to contain
  pointers only. Thus ordinary use of either mandatory evidence channel can
  violate the absolute wording.
- PROPOSED REPLACEMENT TEXT: Define the complete storage boundary,
  including whether local Git objects, named remotes, backups, provider
  logs, transcripts, and indexes are inside or outside it. Permit content
  only in named controlled stores. If chat persistence cannot be excluded,
  chat carries only gate IDs, paths, hashes, and signed responses; content
  review occurs in a separately named contained reader.

### M2 — HG4 does not identify one immutable transfer and conflicts with P7

- EXACT LOCATION: P6 lines 76-77; P7 lines 78-80; HG4 lines 170-172.
- ABUSE MECHANISM: “Per item, forever” omits payload hash, literal excerpt,
  recipient, destination, purpose, time, and whether retransmission or
  mutation is allowed. A mutable reading can be shared repeatedly under an
  old grant. HG4 appears to allow external sharing while P7 says publication
  is CLOSED, with no precedence rule.
- PROPOSED REPLACEMENT TEXT: “Each HG4 authorizes one transmission of one
  exact payload or byte range to one named recipient and destination for one
  purpose before one expiry. Every edit, derivative, retransmission,
  recipient, or destination requires a new HG4. HG4 is an exception only to
  P6 location; it cannot waive P3, P7, HG3, or any content rule and never
  authorizes publication or onward transfer.”

### M3 — HG3 is an unnamed external escape hatch

- EXACT LOCATION: P2 lines 42-46; HG3 lines 166-169.
- ABUSE MECHANISM: No controlling constitution, gate ID, authority,
  evidence format, instrument boundary, or return-path rule is named. A
  session can claim an unspecified outside gate existed or relabel a world-
  contact protocol as a simulation, benchmark, validation plan, or survey.
- PROPOSED REPLACEMENT TEXT: “No external world-contact gate is recognized
  until a ratified amendment names the external authority path and digest,
  gate ID, approver identity, exact authorized object, evidence schema,
  input firewall, and return-path rule. A claim of outside approval without
  every field has no effect.”

### M4 — The exhaustive taxonomy is label-based and Type C is an escape hatch

- EXACT LOCATION: taxonomy lines 83-125; guard lines 230-239.
- ABUSE MECHANISM: The v3 text says excluded artifacts are unlicensed “in
  v2.” No closed schema distinguishes a working note from a protocol,
  simulation, figure, executable, or embedded payload. Any forbidden object
  can be wrapped in Markdown, labelled Type C, and supplied with a formal
  compliance block.
- PROPOSED REPLACEMENT TEXT: Define a closed schema, encoding, extensions,
  allowed AST, attachments, and content fields for A/B/C under the current
  and successor charter versions. Type C permits only draft dictionary rows
  and issue annotations and contains no interpreted claim. The guard rejects
  binaries, links/reparse points, alternate streams, embedded payloads, and
  schema-invalid files rather than trusting labels.

### M5 — “Exact corpus pointers” are not content-addressed

- EXACT LOCATION: P1 lines 39-41; dictionary schema lines 89-92; reading
  dependency block lines 120-123.
- ABUSE MECHANISM: A path, part number, or theorem name can later resolve to
  changed content or assurance status while an approved dictionary remains
  facially valid.
- PROPOSED REPLACEMENT TEXT: “Every row pins repository identity, commit,
  source blob digest, theorem ID, exact statement digest, assurance level,
  and typed-hypotheses digest. Any source revocation, supersession, or digest
  change automatically suspends every dependent dictionary and reading.”

### M6 — The authorship gate is circular and self-assignable

- EXACT LOCATION: HG-RECORD line 134; AUTHORSHIP GATE lines 174-183; OD4
  lines 217-220.
- ABUSE MECHANISM: Any agent can call itself the MATH-lane lead; no session
  ID, external role registry, expiry, or operation scope is named. The
  delegation record must exist before the first authorized write, but
  appending it is itself a write by an unauthorized session. OD4 merely
  authorizes later workspace enforcement rather than requiring completed
  enforcement before HG1.
- PROPOSED REPLACEMENT TEXT: “An external registry identifies the immutable
  writer principal. An operator-authenticated event names that principal,
  charter digest, allowed operations, start, and expiry. The operator or an
  external registrar creates the bootstrap record before credentials are
  granted. Completed, pinned workspace enforcement—not authorization to
  install it—is an HG1 prerequisite.”

### M7 — D6 can import world reference by citation

- EXACT LOCATION: D5-D6 lines 109-119.
- ABUSE MECHANISM: A neutral term can point to a definition whose title,
  citation, or surrounding text supplies physical, biological, mental, or
  empirical denotation. “Structural resemblance, not validation” disclaims
  validation but does not remove the imported referent.
- PROPOSED REPLACEMENT TEXT: “D6 compares only explicitly reproduced formal
  structures and enumerates the exact relation. Citation titles, surrounding
  prose, examples, and named definitions cannot supply denotation to layer
  terms. Literature correspondence involving physical, biological, mental,
  measurement, or reality vocabulary is prohibited inside the layer.”

### M8 — Suspension, violations, and amendment are not an executable state machine

- EXACT LOCATION: guard (d) lines 233-235; lines 241-249.
- ABUSE MECHANISM: Revocation is described as immediate but made visible
  only by a later agent-written record. A violation has no detector,
  adjudicator, incident record, or required transition. Closed state requires
  other artifacts to disappear, encouraging deletion of evidence. A fresh
  amendment has no schema or coexistence rule with the pinned charter.
- PROPOSED REPLACEMENT TEXT: Enumerate PROPOSED, RATIFIED-PENDING-GUARD,
  IN-FORCE, SUSPENDED, and REVOKED states and every authenticated transition.
  Suspension preserves artifacts read-only for audit while disabling use and
  egress. Guard incidents are recorded outside writer control. Amendment
  proposals have a defined governance schema and cannot take force until a
  fresh HG1 atomically supersedes the prior version.

### M9 — The charter embeds the semantic precommitment it says HG2 must gate

- EXACT LOCATION: §4 lines 186-204.
- ABUSE MECHANISM: The charter exposes “persistent internal state,”
  “regulation,” “blind,” and “genuine agency” to every charter reader before
  any dictionary approval. “Non-quotable” cannot prevent model conditioning,
  paraphrase, or confirmation pressure, particularly for the MATH-lane lead
  and independent reviewers.
- PROPOSED REPLACEMENT TEXT: Remove all interpretation sketches from the
  charter. It may name only opaque target IDs and content-addressed formal
  pointers. Candidate mappings begin only after HG1 in a quarantined Type-C
  payload inaccessible to formal-lane and independent-review contexts.

## MINOR

### N1 — Neutral pointers can leak through semantic filenames

- EXACT LOCATION: P6 lines 67-69; guard failure rule lines 235-236.
- ABUSE MECHANISM: A path such as `interpretation/model-consciousness.md`
  carries forbidden semantics even when the surrounding message is only a
  pointer.
- PROPOSED REPLACEMENT TEXT: Require guard-generated opaque fixed-format
  identifiers for files, branches, errors, and external pointers.

### N2 — HG5 is undefined and potentially circular

- EXACT LOCATION: HG5 line 173.
- ABUSE MECHANISM: Every artifact needs an internal filename, but the text
  does not say whether that requires HG5 or whether HG5 means public branding;
  it binds no proposed string, payload, or surface.
- PROPOSED REPLACEMENT TEXT: “HG5 applies only to a public-facing title or
  brand, not an opaque internal ID. It binds exact string, artifact digest,
  and destination, and never substitutes for HG4.”

### N3 — D2 and P5 have no claim-level test

- EXACT LOCATION: P5 lines 62-64; D2 lines 100-102.
- ABUSE MECHANISM: “Same mapping,” “its baseline comparison,” and “each
  discourse” are undefined, allowing a mismatched baseline or artificially
  narrow discourse that omits a relevant overread.
- PROPOSED REPLACEMENT TEXT: Each claim names one baseline-row ID with the
  same dictionary row, source revision, hypotheses, and output quantity.
  Claim and baseline are atomic. Every dictionary blocks a charter-wide
  overread registry plus row-specific overreads.

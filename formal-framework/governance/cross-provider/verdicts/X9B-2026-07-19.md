## New and residual loopholes, severity-ranked

### FATAL 1 -- the asserted continuous external control is not in force

Charter G1/G3/G9 claims a workspace-wide, non-bypassable, fail-closed
control already governs the layer (`426-478`). The implementation is a
read-only function called only when the script is manually run
(`guard:173-210,235-240`). The active pre-commit hook contains no guard
call; no local mandatory hook/runner was found; missing
`research/interpretation/` returns success (`181-183`); no baseline
tree or creation provenance is stored. A PROPOSED-state fixture containing
a hidden pre-HG1 semantic payload and base64 data inside the charter file
returned `failures=[]`, because the sole allowed charter is never passed
through M5-SCHEMA or M5-DIGEST in PROPOSED. This is the original F4
build-ahead route in executable form.

### FATAL 2 -- unverified repository claims can manufacture mechanical PASS

A second isolated fixture set state to IN-FORCE, inserted the real current
guard hash, added arbitrary `HG1` and `HG2-R` lines to a synthetic
registry (no operator event), and placed this schema-invalid reading in
`M5-B-001.md`: world/agency claims, a remote Markdown image, and a
`<script>` element. After binding its raw hash in the fabricated
registry, `check_interpretation_layer` returned
`failures=[]; synthetic_result=PASS`. The cause is exact:
`_m5_digest` searches for an unconstrained filename/hash substring
(`141-149`) and `_m5_pin` searches for any same-line
`HG1 ... sha256=<charter hash>` (`165-170`). This does not create a
lawful gate under A2/A5, but it makes the enforcement state disagree with
the constitution's sole trust anchor.

### MAJOR 1 -- the closed schema is mostly declarative

The schema-invalid reading above passed. Ordinary links/images, scripts,
missing required fields, unclassified sentences, and wrong A/B/C content
are not checked. Reparse points and alternate streams are not inspected.
Thus the implementation still trusts a Markdown filename plus digest more
than the structure required by S1-S3.

### MAJOR 2 -- the state machine is a token, not a transition/control system

The guard extracts one state word and chooses whether filenames are
allowed. It records no predecessor, authenticated transition, source
revocation, suspension, reaffirmation, incident, or atomic supersession.
SUSPENDED permits newly added digest-listed artifacts; REVOKED conflicts
with the charter's evidence-preservation requirement.

### MAJOR 3 -- HG2-R is circular at review time

HG2-R forbids any reading “use, rendering, quotation, routing, or sharing”
before approval (`328-332`), but exact-payload operator review necessarily
requires the operator to render/read that payload. B3 permits content
review in chat (`95-98`) without defining a pre-gate review exception.
The repair therefore makes its own approval procedure literally
unperformable or forces an unlicensed pre-approval rendering.

### MAJOR 4 -- the “inert” grammar is not semantically inert

R2 licenses `not`, `if ... then ...`, `therefore`, `hence`,
`denote`, `where`, and `such that` (`219-226`). These operators
negate, imply, assert consequence, and define; they can combine lawful
sentences into a new unsupported claim. Per-payload human review reduces
the risk but does not make the grammar itself inert as asserted.

### MAJOR 5 -- storage names do not fix storage identity

B1 admits the single named `origin` without pinning its remote identity,
so retargeting the label changes the controlled store without an HG4.
Separately, B1 places provider logs/indexes outside while B3 permits
content in chat during review. Unless persistence is excluded or included
in B1, the required review channel can itself violate P6.

### MAJOR 6 -- digest semantics and dependency binding are inconsistent

“Normative body” has no byte-span/canonicalization definition. The guard
hashes complete worktree bytes, while HG2-R is meant to bind reading,
dictionary, charter, and corpus-pointer digests as one governing relation.
The registry schema and code validate only one filename/raw hash at a
time, so dependency changes cannot trigger the automatic suspensions v4
claims.

### MINOR 1 -- raw worktree hashes are checkout-dependent

No line-ending/canonical-byte policy is pinned. With platform line-ending
conversion, the same Git blob can produce a different worktree SHA-256,
creating false suspension and cross-host gate ambiguity.

### MINOR 2 -- pointer/error enforcement is narrower than claimed

Only artifact filenames are regex-checked. Branches and external pointers
are not. A rejected semantic filename is repeated verbatim in the failure
message, contradicting the neutral-error-string promise.
